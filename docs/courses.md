# 開講科目カタログ（`courses/`）

[README](../README.md) · [データ仕様と収録範囲](data.md) · [自動更新の運用](automation.md)

公開シラバス（理工学系、`https://syllabus.s.isct.ac.jp`）に載っている、ある年度の全開講科目を
年度別・開講元グループ別の JSON にしたものです。アプリはこれを科目検索と時間割の授業情報に使い、
これまで各端末が教務Webシステムの「開講科目検索」で読んでいた部分を置き換えます。
教務Webから読むのは、本人に固有の情報（履修申告・成績・要件区分・推奨マーク）だけになります。

## 出典と読み方

| ページ | URL | 読むもの |
| --- | --- | --- |
| 年度ページ | `/courses/{year}`、`?hl=en` | 開講元（unit）の一覧、所属する区分（学士課程・大学院課程・学位プログラム・H27 年度以前入学者向け）、上位の開講元、日英の名称 |
| 開講元ページ | `/courses/{year}/{school}/{unit}`、`?hl=en` | その開講元の全科目：科目コード、講義名、担当教員、開講元、開講クォーター、シラバス更新日 |
| 科目ページ | `/courses/-/-/-/{id}` | 曜日・時限（講義室）、単位数（講義-演習-実験）、授業形態、使用言語、クラス、メディア利用 |

- 公開ページだけを読みます。ログイン、Cookie、LMS、教務Webには一切アクセスしません。
- AI は使いません。`scripts/syllabus_courses.py` が決まった形の HTML を読み、知らない形のページ
  （列数の違い、未知の授業形態・クォーター表記・日付表記、一覧と科目ページの食い違い）に出会ったら
  その場で実行を止めます。推測した値で埋めて公開することはありません。
- 1 リクエストずつ、0.5 秒以上の間隔をあけて読みます。2026 年度の規模は開講元 253、科目 6978 です。
  日本語は既定の言語で、`?hl=ja` は同じページへのリダイレクトになるため付けません。

## 更新の頻度と新しさ

毎日 1 回（03:23 JST）、次を読みます。

| 読むもの | 対象 | 2026 年度の目安 |
| --- | --- | --- |
| 年度ページ（日英） | 毎回 | 2 |
| 開講元ページ（日本語） | 全開講元 | 約 250（約 37 MB） |
| 開講元ページ（英語） | 当日の輪番のファイルの開講元と、新しい科目・シラバス更新日が変わった科目を載せる開講元 | 数件〜数十件 |
| 科目ページ | 当日の輪番のファイルの全科目と、新しい科目・シラバス更新日が変わった科目 | 平均約 230 |

**輪番**：各ファイルを最後に全件読んだ日を記録し、最も古いもの（未読のものが先）から、合計が年度の科目数の
約 1/30 になるまで選びます。選ばれたファイルは英語一覧と全科目ページを読み直すので、1 つのファイルの
科目ページの事実はすべて同じ日に確かめたものです。各ファイルは約 30 日ごとに全件読み直され、科目数が 1/30 を
超えるファイル（教養科目の `undergraduate-7` など）はその日に単独で読みます。シラバス更新日が変われば、
輪番を待たずにその日のうちに科目ページを読み直します。

データファイルには取得時刻を入れません。事実が変わらなければファイルのバイト列もハッシュも変わらず、
アプリが読み直すこともありません。index の `ts` はそのファイルの内容が最後に変わった時刻です。
一覧から消えた科目はファイルからも消えます（その年度の公開シラバスにない、という事実の反映です）。

## ファイル

`courses/{year}/{group}.json`。グループは開講元の区分と学院（URL の `{school}`）で決めます。

| group | 内容 |
| --- | --- |
| `undergraduate-{school}` | 学院等開講科目・学士課程の開講元（`7` は教養科目群） |
| `graduate-{school}` | 学院等開講科目・大学院課程の開講元 |
| `programs` | 学位プログラムとして特別に設けた教育課程 |
| `legacy` | H27 年度以前入学者向けの開講元 |

1 つの科目が複数の開講元に載っている場合（2026 年度は 1213 科目）、年度ページで最初に出てくる
開講元のファイルに 1 回だけ入れ、`units` に載っている全開講元を記録します。そのため `legacy` などには
他のファイルに既に入った科目は重複して入りません。アプリの取得上限（1 ファイル 4 MiB）を超えないよう、
1 ファイルは数百 KB〜1.5 MB 程度に収まる分け方にしています。

index では `academicYears.{year}.courses` に、その年度の全ファイルを配列で列挙します。

## 1 科目のデータ（`offerings[]`）

| フィールド | 例 | 出典・意味 |
| --- | --- | --- |
| `id` | `"202600215"` | シラバスの講義 ID。先頭 4 桁が年度。教務Web・LMS も同じ ID で同じ開講を指します |
| `code` | `"LAS.P106"` | 科目コード。教務Webの `-01` のようなクラス番号は含みません |
| `title` | `{"ja": "物理学演習第二 English Class", "en": "…"}` | 一覧の講義名（クラス名込み）、日英 |
| `class` | `"English Class"` | 科目ページのクラス。`-` のときは省略 |
| `instructors` | `[{"ja": "…", "en": "…"}]` | 一覧の担当教員、掲載順。英語一覧の人数が違うときは `en` を付けません |
| `unit` | `{"ja": "理工系教養科目", "en": "…"}` | 一覧の開講元表示 |
| `units` | `["0-907-0-110800-0"]` | この科目を載せている開講元すべて |
| `quarters` | `[3, 4]` | 開講クォーター（`3～4Q` を展開） |
| `schedule` | `[{"kind": "weekly", "day": 5, "periods": [7, 8], "room": "M-B107"}]` | 曜日・時限（講義室）を ` / ` で区切った順。`day` は 1=月〜7=日。`オンデマンド` は `on-demand`、`集中講義等` は `intensive`、`申告専用` は `registration-only`、`未定` は `tba`、それ以外の語（インターンシップ、講究等、特課PJ、特課研など）は `other` と掲載どおりの `label`。どの種類にも括弧内の教室があれば `room` に掲載どおり入れます（複数教室も分割しません）。`集中講義等5-8` のように毎週以外の種類に時限が書かれていれば `periods` も入れます |
| `credits` | `{"lecture": 0, "exercise": 1, "lab": 0}` | 単位数（0.5、0.6 などの小数あり） |
| `format` | `{"kinds": ["lecture", "exercise"], "delivery": "in-person"}` | 授業形態。`delivery` は対面型 `in-person`・ハイフレックス型 `hyflex`・ブレンド型 `blended`・ライブ型 `live`・オンデマンド型 `on-demand`・その他 `other`、表記がなければ `null` |
| `language` | `"ja"` | 使用言語。日本語・英語以外は `other`、表記なしは `null` |
| `media` | | メディア利用科目。`-` のときは省略 |
| `syllabusUpdated` | `"2026-09-17"` | シラバス更新日。差分取得の判定に使います。シラバスが未作成の科目（2026 年度は約 1150 科目、一覧では空欄、科目ページでは `-`）は `null` |

ファイルの先頭には `group`（id と日英名）、`source`（年度ページの URL）、
`units`（グループの全開講元：id、学院、区分、日英名、上位開講元）があります。

## 収録しないもの

- **本人に固有の情報**：要件区分（A・B…）、推奨マーク（◎・○）、科目区分（専門科目・他系科目など）、
  履修前提条件の注記、抽選の注記。教務Webの開講科目検索は、ログインした学生の課程から見た値を返すため、
  同じ科目でも学生によって違います。これらはアプリが教務Webから本人の分だけ読みます。
- **シラバス本文**：授業の目的、授業計画、教科書、成績評価など。アプリは科目ページそのものを開きます。
- **教務Webのクラス番号付きコード**（`LAS.I111-01`）。シラバスには載っていません。アプリは LMS の
  shortname からクラス番号を補っています。
- 医歯学系のシラバス。

## 検証

- 構造：`schema/courses.schema.json`。
- 意味：ファイル名の年度と `academicYear`、ファイル名とグループ id の一致、`id` の先頭 4 桁が年度と一致、
  `id` が年度内の全ファイルで一意、`units` の各 id がその年度のいずれかのファイルの `units[]` にあること、
  `periods` が開始 ≤ 終了。
- 縮小の検出：前回公開より科目数が 20% 以上減る読み取りはファイルに書かず、その回は失敗として記録します
  （サイトの一時的な不具合で一覧が空になった場合などに、科目を消してしまわないため）。人が原因を確認します。
- 年度の条件：index にその年度の校暦（`academicCalendar`）がまだない年度は公開しません。アプリは校暦のない
  年度の項目を読めず、index 全体の読み取りが失敗するためです。次年度は校暦が公開されてから載ります。

## 教務Webとの照合（2026-11-22）

教務Webの開講科目検索（LAS 1Q、CSC 3Q、XCO 1Q の 101 科目）を、同じ ID のシラバス科目ページと比べました。
101 科目すべてがシラバスにあり、公開ファイルの曜日・時限・教室・単位数・使用言語は 101 科目すべてで一致しました。
科目数も LAS 1Q で一致しています（教務Web 86、シラバスの開講クォーター「1Q」86）。

## 自動更新

読み取りは GitHub Actions ではなく、状態を持てるホスト（現在は保守者の NAS）の Docker で動かします
（[`ops/syllabus-reader/`](../ops/syllabus-reader/)）。輪番の記録と実行ログはそのホストに残り、リポジトリには
コミットしません。各回の流れは次のとおりです。

1. 最新の main に合わせ、`syllabus_courses.py --state` で読み、ファイルと index を書きます。
2. CI と同じ `validate_datasets.py` と `update_subscription_index.py --check` を通します。
3. NAS では全量テストに通った変更を `syllabus_courses.py --publish` が main に直接公開します。
   公開前に main が進んだ場合は、次回最新の main から読み直します。
4. 公開できた（または変更がなかった）回だけ輪番の記録を進めます。失敗・保留の回に全件読んだファイルは、
   次回もう一度全件読みます。

各回の結果は `state/runs.jsonl` に 1 行ずつ残り、`STATUS_URL` を設定すればそこにも送ります。
公開用の短期トークンは Isct-Data 専用の GitHub App から発行します。[NAS の設定](nas-ci.md) を参照してください。

ローカルでは次のように実行します（`--cache` は取得したページを保存し、再実行で読み直しません。`--state` を
付けなければすべてのファイルを全件読みます）。

```sh
python scripts/syllabus_courses.py --year 2026 --cache .data-runs/syllabus-cache
python scripts/update_subscription_index.py
python scripts/validate_datasets.py
```
